# 08. 월간 요약 · 통계 · 엑셀 내보내기

가계부에 쌓인 거래를 "한눈에 보는 숫자"로 바꾸는 부분입니다. 화면과 엑셀 파일은 **같은 집계 규칙**을 씁니다. 외화는 `krw`로 원화 환산, 환불은 음수, 비중의 분모는 `shareBase`, 상위 카테고리는 `topCategory`로 셉니다.

다만 모든 곳이 한 함수를 부르지는 않습니다. 엑셀(`src/lib/export.ts`), 통계 · 비중 화면, 월간 요약의 "결제수단·카드별" 표는 같은 규칙으로 따로 셉니다. 화면 숫자와 파일 숫자가 맞는지는 `src/lib/report.test.ts`가 테스트용 고정 장부(`src/lib/data/fixtures.ts`의 거래)로 대조합니다. 예외가 하나 있습니다. 엑셀 "카드별 혜택" 시트의 결제액은 환불을 빼기 전 금액이라 화면의 카드별 지출과 다를 수 있습니다(5장).

| 화면 | 경로 | 하는 일 |
| --- | --- | --- |
| 월간 요약 | `/monthly` | 한 달의 수입·지출·순수입·혜택, 카테고리별·일별·결제수단별 |
| 통계 · 추이 | `/stats/trend` | 최근 12개월 수입·지출, 카테고리별 추이 |

집계 함수는 이 문서의 화면 밖에서도 쓰입니다. 규칙을 바꾸면 아래 화면도 같이 바뀝니다.

| 함수 | 쓰는 곳 |
| --- | --- |
| `monthSummary` | 월간 요약(날짜별 합계 `byDay` 포함), 통계 · 추이, 홈(`/home`) |

알림(`deriveNotifications` in `src/lib/notify.ts`)은 실적 구간 임박과 놓친 혜택만 만듭니다. 예산 알림은 예산 기능과 함께 뺐습니다. 알림은 머리글에서 보고 있는 달이 아니라 **오늘이 속한 달** 기준입니다.

## 1. 집계 규칙 — 모든 숫자의 기준

`monthSummary(txns, "2026-09", categories)` 한 번이 그 달의 숫자를 전부 만듭니다. 규칙은 네 가지입니다.

1. **외화는 원화 환산액으로 셉니다.** `krw(t)`가 `amountKrw`를 돌려줍니다. 원화 거래는 `amount` 그대로입니다. `amountKrw`가 없는 외화 거래는 고정 대략 환율(`FX_APPROX`: USD 1,380원, JPY 9.2원)로 환산한 참고값을 씁니다(`src/lib/engine/index.ts`의 `approxKrw`).
2. **환불은 환불한 날의 달에서 빠집니다.** 환불·부분 취소는 `originalTxnId`가 있는 지출 거래로 저장됩니다. 9월 5일 3만 원 결제를 9월 8일에 1만 원 환불하면 9월 지출은 2만 원입니다. 결제가 8월이고 환불이 9월이면 8월은 3만 원, 9월은 −1만 원입니다.
3. **카테고리·카드·일별 건수에는 환불을 넣지 않습니다.** "카페 4건"은 결제 4번이라는 뜻입니다. 엑셀 "월별 요약"의 거래 건수도 환불을 뺍니다. 통계 · 추이 표의 "거래" 열과 "12개월 합계"도 같은 기준(`expenseCount + incomeCount`)이라, 고정 장부의 9월은 어느 화면에서나 같은 건수로 보입니다.
4. **카테고리는 두 벌로 셉니다.** `byCategory`는 상위 카테고리 기준(식비 = 카페 + 외식 + 배달 + …), `bySubCategory`는 거래에 실제로 지정된 카테고리 기준입니다.

### 환불은 어느 달에 들어가나 — 할인 금액만 원결제 달

가계부 숫자와 카드 실적은 **환불한 날이 속한 달**에서 빼고, 할인 금액만 원결제 기준으로 다시 계산합니다. 8월 20일 19만 원 결제를 9월 3일에 취소했다면 다음과 같습니다.

| 어디서 | 반영하는 달 | 어떻게 |
| --- | --- | --- |
| 가계부 집계 (`monthSummary`, 그리고 같은 규칙으로 세는 통계 · 비중·엑셀) | 9월 (−19만 원) | 돈이 실제로 돌아온 달이 9월입니다. 이미 지나간 8월 지출이 나중에 바뀌면 지난 달 결산을 믿을 수 없게 됩니다. 카드 명세서도 취소를 취소한 달에 보여 줍니다. 8월 지출·카테고리·카드별 금액은 그대로 19만 원입니다. 엑셀 "카드별 혜택" 시트의 결제액만 예외로 환불을 빼지 않습니다(5장). |
| 카드 실적 (`monthSpend`, `spendWindow`) | 9월 실적 창 | 환불 거래의 날짜가 들어가는 실적 창(달력 달, 청구 사이클을 정한 카드는 "8/15~9/14" 같은 기간)에서 뺍니다. 원결제가 같은 카드의 실적 대상 결제(실적 제외 업종이 아님)일 때만 빼고, 창의 실적은 0 아래로 내려가지 않습니다. 8월 실적은 바뀌지 않으므로 8월 실적으로 정해진 9월 혜택 구간은 그대로이고, 줄어든 9월 실적이 **10월** 혜택 구간에 영향을 줍니다. 홈·카드 화면의 9월 실적 진행 막대("○월 구간용")도 그만큼 줄어듭니다. |
| 할인 금액 (`calcCard`, `effectiveAmount`) | 8월 | 8월 결제를 환불 뒤 유효 금액(이 예에서는 0원)으로 다시 계산하므로 8월에 받은 혜택(월간 요약 "받은 혜택", 엑셀 "월별 요약"·"카드별 혜택")이 줄어듭니다. 환불 거래 자체는 혜택 계산 대상이 아닙니다. |

가계부 집계와 카드 실적이 같은 기준(환불한 날)이라 "지출에서는 빠졌는데 실적에는 남아 있는" 어긋남이 없습니다(청구 사이클 카드는 창의 경계만 다름). 테스트는 `report.test.ts`("환불은 환불한 달 지출에서 빠지고…")와 `engine.test.ts`("환불은 환불한 날이 속한 달의 실적에서 뺀다…")가 지킵니다.

그래서 9월 월간 요약에서는 쇼핑이 −19만 원처럼 **음수 카테고리**가 생길 수 있습니다. 비중(%)은 이 음수 항목을 빼고 계산합니다(아래 "비중의 분모").

### 비중의 분모 — `shareBase`

비중은 **양수 항목의 합**으로 나눕니다. 순지출(결제 − 환불)로 나누면, 이전 달 결제의 환불 때문에 음수가 된 카테고리가 있을 때 나머지 카테고리 비중의 합이 100%를 넘습니다(예: 식비 58% + 생활 28% + 교통 25% + 구독 3% = 114%). 순지출이 0 이하이면 도넛이 아예 그려지지 않습니다.

- 월간 요약 표(`categoryRows`), 통계 · 비중(카테고리·카드·결제수단), 엑셀 "카테고리별 지출" 시트가 모두 같은 규칙을 씁니다.
- 분모는 그 표의 행 단위로 정합니다. 상위 행은 상위 카테고리 합(`byCategory`), 하위 행("식비 (하위 미지정)" 포함)은 하위 카테고리 합(`bySubCategory`)으로 나눕니다. 엑셀 시트의 행은 거래에 지정된 카테고리 단위라 화면의 하위 행과 같은 숫자입니다. 같은 상위 안에 음수 하위가 있는 달에는 하위 행 비중이 상위 행보다 클 수 있습니다(예: 배달 환불 −2만, 카페 5만, 교통 3만 → 식비 50%, 카페 62.5%).
- 음수 항목은 도넛·막대에서 빼고 **표에만** 보여 주며, 비중 칸에 "환불"이라고 적습니다. 그래프 아래에 "쇼핑 −190,000원: 이전 달 결제의 환불이 이번 달 결제보다 커서 음수예요"처럼 이유를 적습니다.
- 이때 도넛 가운데 숫자는 순지출이 아니라 양수 항목 합이라 이름을 "지출 합계" 대신 "비중 기준 합계"로 바꿉니다. 표의 금액 합계는 그대로 순지출입니다.
- 엑셀에서는 음수 행의 비중 칸을 비워 둡니다.

```ts
const s = monthSummary(txns, "2026-09", categories);
s.income        // 수입 합
s.expense       // 지출 합 (결제 − 환불)
s.net           // 순수입 = 수입 − 지출
s.byCategory    // { food: 295100, transport: 125000, ... }
s.bySubCategory // { "food.cafe": 27600, "food.mart": 146000, ... }
s.byDay         // { "2026-09-03": { income, expense, count } }
```

### 증감률 — `pctChange`

지난달 값이 0이면 증감률은 계산할 수 없으므로 `null`을 돌려주고 화면에는 "비교 불가" 또는 "지난달 기록 없음"이라고 씁니다. 0%로 보여주면 "변화 없음"으로 잘못 읽히기 때문입니다.

## 2. 월간 요약 화면 (`/monthly`)

맨 위 `내역 | 월간 요약` 전환은 거래 목록과 같은 `ViewSwitch`(`src/components/shell.tsx`)입니다. 모양은 Seg지만 페이지 이동이라 `<nav>` 안의 링크이고, 지금 화면에 `aria-current="page"`가 붙습니다. 그 아래는 화면 순서대로 다음과 같습니다. 기록이 없는 달에는 이 내용 대신 "기록이 없어요" 안내만 나옵니다.

1. **핵심 숫자 4개.** 수입·지출·순수입·받은 혜택입니다.
   - 수입·지출·순수입은 지난달 대비 증감을 보여 줍니다. 지출은 늘면 빨강(▲ 늘었어요), 수입·순수입은 늘면 초록입니다. 색은 `deltaTone(차이, 늘면좋음)` 하나로 정합니다(좋아짐 `text-green-700`, 나빠짐 `text-red-700`, 같음 `text-muted`). 카테고리 표·막대의 증감도 지출 기준으로 같은 함수를 씁니다. 색만으로 방향을 알리지 않도록 ▲▼ 기호와 문장을 함께 씁니다.
   - 받은 혜택 칸("받은 혜택 (참고값)")은 증감 대신 "지난달 N원 · 놓친 혜택 N원"을 보여 줍니다. 지난달 기록이 없으면 "지난달 기록 없음"이라고 씁니다.
2. **업종 미분류 안내.** 그 달 결제 중 업종을 알 수 없는 것이 있으면 핵심 숫자 바로 아래에 "업종 미분류 N건 · 확인하기"가 나옵니다. 누르면 `/transactions?unclassified=1`로 이동해 그 결제들만 보고 업종을 고칠 수 있습니다.
   - 업종 미분류는 `isUnclassified(t)`(`src/lib/stats.ts`) 하나로 정합니다. 카드(신용·체크)로 낸 지출이고(`cardId`가 있음), 환불이 아니고, 업종(`industryOf` = 저장된 업종 → 가맹점 사전)이 없거나 "기타"(`etc`)인 결제입니다.
   - 업종은 카드 혜택을 맞출 때만 쓰이므로 카드 결제만 셉니다. 현금·계좌이체(월세 등)나 카드가 비워진 결제는 업종이 없어도 미분류가 아닙니다.
   - AI 분류는 모르는 가맹점을 `etc`로 답하고 `etc`로는 어떤 업종 혜택도 맞지 않기 때문에 미분류로 셉니다. 사용자가 일부러 "기타"를 고른 결제도 안내에 남습니다.
   - 업종을 모르면 업종 조건만 걸린 카드 혜택(카페·편의점 할인 등)을 맞출 수 없기 때문에 사용자가 직접 확인하게 합니다. 가맹점 목록이 붙은 혜택은 업종을 몰라도 가맹점 이름으로 맞춥니다.
   - 업종이 없어도 집계(월간 요약·통계·엑셀)에서는 빠지지 않습니다. 집계는 카테고리 기준이고, 업종은 "미분류"라는 표시로만 나옵니다.
3. **카테고리별 지출.** 오른쪽 위 `그래프 | 표`로 전환합니다.
   - 그래프: 도넛(비중) + 순위 막대(금액, 비중, 건수, 지난달 대비). 막대를 누르면 `/transactions?cat=식비id`로 이동해 그 카테고리 거래만 봅니다.
   - 표: 카테고리 · 이번 달 · 비중 · 지난달 · 증감 · 건수 · 예산 사용. 상위 카테고리 왼쪽 `›`를 누르면 하위 카테고리가 펼쳐집니다. 상위 카테고리에 직접 지정된 거래가 있으면 "식비 (하위 미지정)" 행이 따로 생겨 합계가 맞습니다. 이번 달은 0원이어도 지난달에 쓴 카테고리는 행이 남아서 "줄어든 것"도 보입니다(`categoryRows`).
4. **일별 지출.** 1일~말일 세로 막대 또는 표. 일평균(지난 달은 말일까지, 이번 달은 오늘까지로 나눔)과 가장 많이 쓴 날을 함께 보여줍니다.
5. **결제수단·카드별.** 카드마다 지출·받은 혜택·놓친 혜택, 현금·계좌이체는 지출만 보여 줍니다. 지출은 환불을 뺀 순액입니다.
   - 직접 추가한 카드를 지우면 그 카드의 거래는 `cardId`만 비워지고 `payType`(신용/체크)은 남습니다(`removeCustomCard`, `src/lib/store.tsx`·`src/lib/db.ts`). 이런 결제는 결제수단 이름("신용카드"/"체크카드") 행으로 모이고 혜택 칸은 "-"입니다. 엔진의 혜택 계산, 엑셀 "카드별 혜택" 시트, 업종 미분류 집계에서도 빠집니다.
6. **AI 인사이트.** 기록이 있는 달에만 요청합니다(빈 달에 0으로 채운 집계로 AI를 부르지 않음). AI가 실패하면 템플릿 문장을 씁니다. 템플릿은 이름의 받침에 따라 조사가 틀리지 않도록 "696,100원으로", "식비 카테고리(42.4%)예요"처럼 받침이 정해진 말로 끝맺습니다.

> **놓친 혜택이 두 가지인 이유.** 표의 놓친 혜택은 결제마다 "가장 유리한 보유 카드였다면"의 차액을 더한 값입니다. 핵심 숫자의 놓친 혜택은 엔진이 한도를 나눠 쓰는 것까지 고려해 한 달 단위로 배분한 값입니다. 두 결제가 같은 카드의 같은 월 한도를 노리면 결제별 합은 그 한도를 두 번 세므로, 결제별 합이 월 배분값보다 클 수 있습니다. 자세한 배분 방법은 [04. 혜택 계산 엔진](04-benefit-engine.md)의 15.4절(`computeMonth`의 놓친 혜택 그리디 배분)에 있습니다.

**이 달 엑셀로 받기**는 그 달 1일~말일을 기본 열로 바로 내려받습니다. 넓은 화면(Tailwind `md`, 폭 768px 이상)에서는 오른쪽 위에, 모바일에서는 페이지 맨 아래에 있습니다. 맨 아래 **기간·열을 골라 내보내기** 링크는 내보내기 화면을 그 기간(`?from=…&to=…`)으로 열어 줍니다. 기록이 없는 달에는 오른쪽 위 버튼이 비활성이고, 맨 아래 버튼과 링크는 나오지 않습니다.

## 5. 엑셀 내보내기 (`/settings/export`)

### 화면에서 고르는 것
- **기간**: 이번 달 · 지난 달 · 최근 3개월 · 올해 · 전체 기간, 또는 날짜 직접 입력. 시작일이 종료일보다 늦으면 막습니다. 다른 화면에서 `?from=2026-09-01&to=2026-09-30`으로 기간을 넘겨 열 수 있습니다.
  - 프리셋(미리 정해 둔 기간 버튼)은 달력상 오늘이 아니라 **머리글에서 선택한 달**(`store.month`) 기준입니다. 기간을 넘기지 않고 열면 기본값도 그 달 1일~말일입니다.
  - "올해"는 선택한 달이 속한 해의 1월 1일~12월 31일이라 미래 날짜까지 들어갑니다. "전체 기간"은 가장 이른 거래 날짜~가장 늦은 거래 날짜입니다.
- **파일 형식**: 엑셀(.xlsx, 시트 4장) 또는 CSV(거래내역만, UTF-8).
- **거래내역에 넣을 열**: 사용 카드·할부 / 받은 혜택·적용 규칙 / 놓친 혜택·최적 카드 / 메모·품목 / 혜택 조건 필드.
- **미리보기**: 실제 파일과 같은 함수(`buildExport`)로 계산한 지출·수입·혜택 합계와 시트별 행 수가 바로 보입니다.

파일은 브라우저에서 만들어지고 서버로 거래를 보내지 않습니다.

### 파일 구조 (.xlsx)

| 시트 | 한 줄 | 열 |
| --- | --- | --- |
| 거래내역 | 거래 1건 | 날짜, 시각, 구분(지출/수입/환불), 가맹점, 대분류, 소분류, 업종, 지출(원), 수입(원), 결제수단 + 고른 열. 외화 거래가 있으면 통화·원래 금액(소수 둘째 자리까지) |
| 월별 요약 | 한 달 | 월, 기간(한 달 전체 / 1일~10일), 수입, 지출, 순수입, 받은 혜택, 놓친 혜택, 거래 건수 |
| 카테고리별 지출 | 대분류·소분류 | 대분류, 소분류, 지출, 비중(%), 건수 |
| 카드별 혜택 | 카드 1장 | 카드, 결제 건수, 결제액, 받은 혜택, 놓친 혜택 |

- 지출과 수입을 다른 열에 두고 **환불은 지출 열에 음수**로 넣습니다. 그래서 엑셀에서 지출 열을 SUM하면 화면의 "지출"과 같습니다(테스트로 확인).
- 마지막 줄은 합계이고, 실제 `SUM()` 수식과 미리 계산한 값을 함께 넣습니다. 수식을 다시 계산하지 않는 뷰어에서도 숫자가 보입니다.
- 날짜는 엑셀 날짜 셀(`yyyy-mm-dd`), 금액은 숫자 셀(`#,##0`), 외화 원래 금액·주유량(L)은 소수 셀(`#,##0.##`, USD 45.5가 46으로 보이지 않게), 비중은 퍼센트 셀(`0.0%`)이라 정렬·필터·합계가 바로 됩니다. 첫 줄은 굵게 고정되고 필터가 걸려 있습니다.
- 월별 요약의 놓친 혜택은 한 달 전체가 기간에 들어가면 화면과 같은 월 배분값을, 달 중간에서 끊기면 그 기간 결제별 차액 합을 씁니다. "기간" 열에 어느 쪽인지 적혀 있습니다.
- 결제수단은 `credit` 같은 코드가 아니라 "신용카드"처럼 한국어로 나갑니다.
- "카드별 혜택" 시트는 카드가 있는 결제(`isCardPay`: 지출이고 환불이 아니고 `cardId`가 있음)만 셉니다. 그래서 결제액은 **환불을 빼기 전** 결제 합계입니다. 월간 요약 "결제수단·카드별"의 지출은 환불을 뺀 순액이라, 환불이 있는 달에는 두 숫자가 다릅니다. 고정 장부 9월의 현대 ZERO Edition3은 시트 결제액이 206,500원, 화면 지출이 177,500원입니다(무신사 부분 환불 29,000원 차이).

### `.xlsx` 작성기는 어떻게 동작하나 (`src/lib/xlsx.ts`)

`.xlsx`는 사실 **XML 파일 몇 개를 zip으로 묶은 것**입니다. 필요한 기능이 적어서(시트 여러 장, 머리글 굵게, 숫자·날짜·퍼센트 서식, 고정, 필터, 합계) SheetJS 같은 큰 라이브러리 대신 직접 만듭니다.

```
[Content_Types].xml            각 파일의 종류
_rels/.rels                    "이 패키지의 본문은 xl/workbook.xml"
xl/workbook.xml                시트 목록
xl/_rels/workbook.xml.rels     workbook → 시트들, styles
xl/styles.xml                  글꼴(맑은 고딕), 머리글 배경, 셀 스타일 9종(숫자 서식은 #,##0 · #,##0.## · 0.0% · yyyy-mm-dd)
xl/worksheets/sheet1.xml …     셀
```

- 문자열 셀은 `inlineStr`로 넣습니다. 공유 문자열 표를 따로 만들 필요가 없고, **`=`로 시작하는 가맹점명도 수식으로 실행되지 않습니다.**
- XML에서 허용하지 않는 제어 문자(영수증 인식 결과에 섞일 수 있음)는 지웁니다. 남아 있으면 엑셀이 파일을 못 엽니다.
- 시트 이름은 엑셀 규칙대로 31자 이하로 자르고, `[]:*?/\`는 공백으로 바꿉니다. 대소문자를 무시하고 이름이 겹치면 28자로 자른 뒤 " 2"처럼 번호를 붙입니다(`sheetNames`).
- zip은 압축하지 않는 "저장" 방식에 CRC32 검사값을 붙입니다. 거래 수천 건이어도 몇 MB 이하라 충분합니다. 같은 입력이면 같은 바이트가 나오도록 파일 시각을 고정합니다.

CSV는 첫 시트(거래내역)만 내보내며(`toCsv`) 두 가지를 챙깁니다.
- 맨 앞에 UTF-8 BOM(파일이 UTF-8임을 알리는 앞머리 3바이트)을 붙여 엑셀이 한글을 깨뜨리지 않습니다.
- `= + - @`(와 탭·CR)로 시작하는 글자 앞에 `'`를 붙여 **CSV 수식 주입**을 막습니다. 영수증 인식 결과처럼 외부에서 온 글자가 엑셀에서 명령으로 실행되는 공격을 막는 표준 방법입니다.

CSV에는 **합계 행을 넣지 않습니다**. CSV는 다른 가계부 앱으로 옮길 때 쓰는데, 합계 줄이 있으면 그 앱이 거래 한 건으로 잘못 가져가기 때문입니다(`toCsv(sheet, footer = false)`). 합계가 필요하면 엑셀(.xlsx)을 쓰면 됩니다. 내보내기 화면 미리보기도 CSV일 때는 "합계 행"을 표시하지 않습니다.

### 검증
- `src/lib/report.test.ts`가 고정 장부로 "거래내역 지출 합 = 월간 요약 지출", "받은 혜택 합 = 엔진 월 합계", "카테고리별 합 = 지출, 비중 합 = 100%"를 확인합니다.
- 같은 파일에서 만든 zip을 직접 풀어 CRC, 날짜 셀, 합계 수식, 필터, 고정, 시트 이름 규칙을 확인합니다.
- 개발 중에는 생성한 파일을 파이썬 `openpyxl`로도 열어 4개 시트와 서식이 정상인 것을 확인했습니다.
