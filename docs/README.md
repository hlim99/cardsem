| 2 | [02. 기술 스택](02-tech-stack.md) | 어떤 기술을 왜 골랐고, 이 프로젝트 어디에 쓰였나? |

| 4 | [04. 혜택 계산 엔진](04-benefit-engine.md) | 결제 한 건의 카드 혜택은 어떤 순서로 계산되나? 놓친 혜택은? |

## 여러 문서에 흩어진 기능

아래 세 기능은 문서 하나에 모여 있지 않습니다. 찾을 때 이 표를 보세요.

| 기능 | 무엇인가 | 읽을 곳 |
| --- | --- | --- |
| 어드민 (`/admin/*`) | 카드 약관 원문 입력 → LLM(대규모 언어 모델, 여기서는 OpenAI) 정규화 → 검수 → 반영. 로그인 모드에서는 `app_metadata.role`이 `admin`인 사용자만 씁니다 | [01](01-overview.md) 5.3 "어드민", [03](03-architecture.md) 1·3.4절, [05](05-receipt-ai.md) 11절 |
| 직접 추가 카드 (`/cards/custom`) | 목록에 없는 카드를 사용자가 만듭니다. `addCustomCard`로 저장하고, 로그인 모드에서는 `card_products`에 `owner_id = 본인`으로 들어갑니다 | [01](01-overview.md) 5.3, [03](03-architecture.md) 3.9절, [07](07-data-model.md) 4.6절 |
| 알림 (`/notifications`) | `src/lib/notify.ts`의 `deriveNotifications`가 저장 없이 매번 계산합니다. 종류는 `tierSoon`(실적 구간 임박)·`missed`(놓친 혜택) 두 가지입니다. 예산 알림은 뺐습니다 | [01](01-overview.md) 5.3 "홈 · 거래", [03](03-architecture.md) 3.2절 |

## ERD용 SQL

`docs/erd/cardsem_erdcloud.sql`은 ERDCloud(웹 ERD 그리기 도구)에 붙여 넣어 ERD 그림을 만드는 SQL입니다. ERDCloud가 읽도록 MySQL 문법으로 썼기 때문에 Supabase에서는 실행할 수 없습니다. 실제 DB 스키마는 `supabase/schema.sql`과 `supabase/migrations/`에 있습니다([07](07-data-model.md) 6·10절).
